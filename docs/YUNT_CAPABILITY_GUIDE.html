Yunt: what it can do, what it will not do

A practical guide for operational conversations. It separates hard controls from model interpretation, gives concrete examples, and calls out the edges where a person must still decide.

Prepared 13 September 2026 · Living operational guide

The selling points

Email-first operation
Send invoices, ask a question, approve a proposed category, create a purchase request, or request a report without opening the dashboard.
Records before language
The model interprets intent, but it cannot invent figures or write arbitrary data. Database tools own the actual read, draft, approval and write.
Human-controlled changes
Classification changes and purchases are staged, restated, then require an exact reply before the database changes.
Presentable evidence
Reports return designed XLSX, PDF or SVG attachments: clear title, criteria, hierarchy, headers, tables or charts—not a text dump.

How the guardrails work

Person emails request→Yunt reads permitted context→Tool reads / stages exact record→Yunt restates effect→Exact confirmation→Database writes one permitted action
Important distinction: natural language selects an option; it never substitutes for authority. The model can identify “item 2” or “the diesel category,” but the database receives the hidden proposal or draft ID resolved from the email thread—not a free-form category or invoice-row command.

Answers to the operational “what if?” questions

1. What makes an invoice a duplicate?

For XML invoices, the duplicate identity is issuer RUT + document type + folio. Folio alone is deliberately insufficient: different suppliers may use the same number. A repeated document is reported and skipped; it is not loaded twice.

Example: supplier A’s invoice 101 and supplier B’s invoice 101 are different. Re-sending supplier A’s invoice 101 is a duplicate.

2. What does the arithmetic check trust?

It uses deterministic XML fields: line quantity × unit price versus the declared line amount, and document totals where applicable. The test found 40 × CLP 9,000 = CLP 360,000 while the XML declared CLP 412,000; Yunt flagged the discrepancy and did not alter the filing.

If a supplier omits or misplaces a required deterministic field, the relevant arithmetic check cannot be proved. That becomes a data-quality limitation or rejection/flag, never a model-made correction.

3. Can confirmation survive Q&A in the same conversation?

Yes, but safely. A question after a proposal does not apply anything. Yunt answers briefly and sends a fresh confirmation message; the final SÍ, ADELANTE / YES, GO AHEAD must directly reply to that fresh message. It does not silently connect a “yes” to a proposal several messages back.

4. What does “partial approval” actually change?

Only the chosen proposal. The email wording is interpreted, then resolved to a hidden proposal ID from that thread. The application writes only that proposal’s sealed invoice lines. Any new replacement category is restated and separately confirmed before writing.

“Apply item 2 only” cannot accidentally apply items 1 and 3.

5. Is confirmation a hard rule or just model behavior?

It is both. The agent is instructed to require the exact first line, and the database validates the reply’s sender, the exact confirmation message it replies to, action, target and one-time token. A casual “yes” or a confirmation in the wrong reply position does not perform the write.

6. Can a different topic start in the same thread?

Yes. A report question can follow invoice discussion or purchasing in a thread. The agent uses the reply context only for an outstanding action; a new report request is handled by the report tools. Do not use an old confirmation phrase while changing topic: a confirmation must stay a direct reply to Yunt’s current confirmation message.

7. How free is the model?

It can understand supported requests, choose among its tools, explain a result and ask for missing facts. It cannot browse the internet, contact suppliers, change invoice source amounts, issue an unconfirmed order, or access production/farm data that is not available through a tool. Out-of-scope questions are refused and recorded for later product learning.

8. Are spreadsheet and PDF reports presentation quality?

Yes. The workbook uses a dark title band, report title, criteria block, frozen headers, readable widths and number formatting. The PDF has a branded header, scope/criteria, summary cards, a structured table with alternating rows and pagination footer. Charts have a deliberate visual frame and chronological time order.

The design is code-controlled and repeatable. It is not an open-ended “make any document style” agent like a general document-design tool.

9. Why might a clarification arrive as a separate email?

That was a historical threading defect: an outgoing message used the wrong identifier, so Outlook could not attach it to the conversation. The reply helper now uses the inbound RFC Message-ID (or the immediate message being replied to) to retain the conversation. A new topic may still intentionally begin a new thread; an ordinary clarification should not.

10. How much room is there to improve reports?

Substantial room within the fixed, deterministic renderer: palette, typography, logo, cover/title hierarchy, section order, cards, tables, chart types, legends, annotations, page sizing and workbook tabs can all be improved without giving the model control over figures. The right approach is to design templates in code and visually test every artifact.

11. Does Yunt learn the two-quotation requirement too late?

No. The current order flow preflights before it asks for purchase-order confirmation. Above CLP 500,000, fewer than two recorded quotes prevents the order draft itself. The database repeats the same rule at final issuance so it cannot be bypassed. Yunt should ask for the missing second quote, not offer a confirmation then fail.

A live repair also ensures that this expected preflight returns a short, usable request for the second quotation instead of leaving the conversation without an answer.

12. Does the purchase-order PDF arrive by email?

Yes. Once the person directly confirms the prepared order, Yunt sends the finished purchase-order PDF to the requester’s email. It does not tell them to download it from the dashboard, and it does not contact the supplier.

Concrete operating examples

Invoices

Ask: Attach a ZIP of XML invoices.

Result: “Received 6 documents, 7 lines, 1 discrepancy.” Then grounded findings and category proposals arrive. Duplicate documents are skipped.

Report

Ask: “Send me a PDF of purchases grouped by month during 2025.”

Result: A concise answer and a PDF attachment with the same date criteria visible in the document.

Purchase request

Ask: “I need 20 bags of mineral salt for Raíces Estate on 2026-10-30.”

Result: A restated request. If the year is absent, Yunt asks for it rather than guessing.

Purchase order

Ask: Provide supplier, agreed price and quote(s), then ask Yunt to prepare the order.

Result: If required evidence exists, an exact order restatement and confirmation; after confirmation, a PDF by email.
